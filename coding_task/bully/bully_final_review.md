# Portal 5 Defensive Bully — Three-Plan Comparative Synthesis and Final Build Design

You are operating as a principal software architect, AI systems architect, senior security engineering architect, and critical design synthesizer inside the existing Portal 5 repository checkout:

`https://github.com/ckindle-42/portal-5`

This task follows three independent comprehensive Defensive Bully design efforts.

Each effort reviewed the same project and produced the same 9-document design package, but each came from a different reasoning/model perspective and therefore differs in architectural detail, interpretation, prioritization, and implementation strategy.

Your task is to **fully read, trace, compare, challenge, reconcile, and synthesize all three design packages into one final authoritative plan**.

This is not a vote.

This is not a majority-wins exercise.

This is not a superficial merge.

This is not a request to select one plan and discard the other two.

This is also not an excuse to redesign the system from scratch while ignoring the work already done.

The objective is:

> Determine what all three plans independently agree on, understand precisely why they differ where they differ, trace those disagreements back to the actual Portal 5 code and architecture, use those differing viewpoints to investigate further, and produce a stronger final Defensive Bully design/build package than any one plan individually.

The project remains Portal 5.

The original Defensive Bully concept remains the same.

The current repository remains the implementation source of truth.

The three design packages are architectural evidence and competing hypotheses.

# Source-of-Truth Hierarchy

Use the following authority order when resolving disagreements:

1. current live Portal code at HEAD
2. observable runtime behavior
3. executable tests and validation
4. current configuration
5. current runtime/data contracts
6. recent relevant git history
7. facts independently agreed upon by all three plans
8. evidence-backed arguments from individual plans
9. prior Defensive Bully design/handoff documents
10. unsupported assertions in any plan

Agreement between the three plans is important evidence.

It is **not automatically truth**.

If all three inherited the same incorrect assumption, current code wins.

Likewise, a minority opinion from one plan may be correct if the code supports it.

The purpose of this task is not to answer:

> Which plan is best?

It is to answer:

> What does the combination of three independent deep reviews teach us that no single review could?

And then:

> Given their agreements, their disagreements, current Portal reality, and the new questions exposed by those disagreements, what is the strongest final Defensive Bully architecture we can now design?

The final result should be **better than K3, better than O48, and better than SOL individually**.

Where all three agree and current code supports them, preserve that convergence.

Where they disagree, investigate.

Where one is right, use it.

Where each contains part of the answer, synthesize them.

Where all three missed something, add it.

Where all three inherited a bad assumption, remove it.

Do not compromise for the sake of consensus.

Do not maximize complexity.

Do not minimize effort.

Design the strongest coherent system.

The end state of this task should be:

> **The Defensive Bully design is finished. The final build program is finished. The next session can convert that accepted build program into coding-agent execution tasks and build the complete system.**
