# SUBSTRATE_MIGRATION_V1 — rollup

`TASK_RAG_SUBSTRATE_MIGRATION_V1` (program `PROGRAM_RETRIEVAL_AND_COMPLIANCE_V1`
track T2). Built on T1's byte-identical seam + stage-set stamp.

**Migration unit:** the compliance / OT RAG KB — 23 documents (13 NERC CIP
standards + a 92-page NIST SP 800-82r3 architecture slice + 9 synthetic figure
docs), the corpus of `tests/fixtures/rag_eval_corpus/`. This is the single
consumer with a real corpus, a labelled 42-query set, and a committed baseline
(`retrieval_eval_baseline.json`); it is also the use case in
`docs/RAG_COMPLIANCE_QA_REALIGNMENT_V1.md`. The other kb_search workspaces have
no corpus or query set on this machine — see "Unmigrated consumers" below.

Corpus assembled from `manifest.yaml`: the 13 CIP PDFs and NIST slice fetched
from nerc.com / nvlpubs.nist.gov, the 9 synthetic figure docs regenerated by the
README builder. Operator OT-policy PDFs (distractor-only, no labelled queries)
were omitted; two `also_accept` entries are therefore unscoreable and those
queries fall back to their `target_file`.

### P3.1 — figure-scoped visual index (O7)

**Structural result (measured):** with `RAG_VISUAL_SCOPE=figures` the visual arm
holds **16 rows** vs the baseline's **435** — 419 of 435 page images (96%) were
prose pages the text arm already covers, VL-embedded a second time and searched
with the same text qvec. This is the collision `VL_TEXT_GATE` was tuned to
referee. Text chunks unchanged (1628). Ingest saved ~all 419 redundant page
embeds (~12 min at ~1.7 s/embed).

**Recall delta (measured):** none where it matters. diagram r@1 0.952 → 0.952,
mixed r@1 1.0 → 1.0, prose r@1 0.812 → 0.812, prose r@5 0.938 → 0.938. Prose MRR
0.884 → 0.865 (rank shuffling in positions 2–5). The 419 removed prose
page-images never produced a correct top hit the text arm did not already have —
they were pure redundancy, and the collision `VL_TEXT_GATE` refereed was
manufactured by the ingest. **Adopt figure-scoping for this KB.**

Query latency is unchanged (~27 s) — it is bound by the VL reranker scoring
~15 page images per query, and figure-scoping leaves ~16 in the arm, so the
per-query rerank width is the same. The saving is entirely at ingest.

### P3.2 — docling HybridChunker (O5); `docling` vs `fixed`

`docling.chunking.HybridChunker` imports at the pinned docling `2.99.0` with
`transformers 5.16.1` intact — the `docling >= 2.100` transformers-cap conflict
the task warned about does not bite at the pin.

**The void verdict resolves in docling's favour, on prose, decisively.** The
retired comparison (`structured` LOST to `fixed`, prose r@1 0.875 → 0.750) used a
hand-rolled section-boundary regex; docling's own layout-aware chunker was never
in it. Re-run as `docling` vs `fixed` on this corpus:

| | fixed (s1) | docling (s2) |
|---|---|---|
| prose r@1 | 0.812 | **0.938** (+2 queries) |
| prose r@5 | 0.938 | **1.000** (no prose gap) |
| prose MRR | 0.865 | **0.958** |

- **`prose-cip-07`** ("how does CIP-002 categorize BES Cyber Systems") — the
  canonical failure the realignment doc flagged as *"NOT in the top 5 on the
  shipping configuration, at every τ"* — is now **rank 1** on `cip-002-5.1a`,
  with a real page locator (33). The two options the realignment doc said fix it
  (structure chunking, unified fusion) were rejected on aggregate; **docling's
  chunker fixes it without any aggregate cost to prose.**
- `prose-cip-04` traded down to rank 3 (`cip-003-9` outranks `cip-007-6` on a
  ports-and-services query); net prose is +2.
- Every chunk carries `prov.page_no` (100%) and a heading path (98%) — O5's
  discarded provenance, and the proper source of P2's O2 `page` field.

**diagram r@1 0.952 → 0.762 is a τ artifact, not a docling regression.** The
docling chunker only changes the *text* arm. `VL_TEXT_GATE` boosts the visual
page only when `top_text_sim < τ`; a docling chunk that lexically overlaps a
diagram query ("which valve is anti-surge") scores higher than a blind slice
did, so the gate reads the text arm as confident and the figure page loses to
it. τ = 0.72 was fitted to the *fixed* chunker's text-sim distribution — see the
τ re-decision. diagram r@5 stays 1.000, so the figure page is still retrieved,
just not ranked first at this τ.

**Adopt docling for this KB, contingent on the τ re-fit.**

### P3.3 — BM25 sparse arm (O4); lexical-decoy false-positive rate

Lexical-decoy set (`queries_lexical.yaml`, 8 queries) added first. **Dense-only
baseline (figure-scoped, no BM25): 7/8 at rank 1.** The one miss is `lex-05`
("how frequently must an ESP be reviewed") → returns the synthetic `esp_plant_b`
drawing instead of `cip-005-7` — the dense retriever is pulled by the "electronic
security perimeter" overlap. This is the number the BM25 arm (s3) must not
degrade; a sparse arm that ranks "mentions ESP" higher would make it worse, not
better.

**Docling-chunker dense-only decoy baseline (s2): still 7/8, but a different
7/8.** `lex-05` (the ESP-review decoy the fixed chunker missed) is now **rank 1**
on `cip-005-7` — docling's section chunk beats the synthetic drawing. `lex-07`
("CIP-009-6 recovery plan") traded down to rank 3 (returns `cip-008-6`). Net
unchanged; the docling chunker moves *which* decoy is hard, not how many.

**s3 (docling + BM25 α = 0.3), measured:**

| set | metric | s2 (dense only) | s3 (+BM25) |
|---|---|---|---|
| prose (main, 16) | r@1 | 0.938 | **1.000** |
| prose | MRR | 0.958 | **1.000** |
| lexical decoy (8) | r@1 | 0.833 (7/8; `lex-07` rank 3) | **1.000 (8/8)** |
| diagram (21) | r@5 | 1.000 | 0.952 |
| diagram | MRR | 0.881 | 0.827 |

- **BM25's marginal contribution (reported separately, never averaged):** it
  tie-breaks the last two imperfect prose queries to rank 1 and fixes the one
  decoy the dense arm missed. On a query that *names* an identifier
  (`CIP-009-6`, `CIP-012-2`), the lexical arm correctly ranks the standard
  itself above the standards that merely cross-reference it — exactly the job.
- **Cosmetic / decoy false-positive rate: 0/8** on the decoy set. The
  "mentions-the-identifier" failure the decoy set was built to catch did **not**
  happen on prose or on the decoys.
- **Where BM25 costs:** one **diagram** query drops out of r@5 (1.000 → 0.952)
  and diagram MRR falls 0.881 → 0.827 — a BM25 hit on a prose chunk that
  contains the query's noun ("valve", "relay") outranks the figure page. Diagram
  queries were not in the decoy set (only 2 of 8 are `diagram_only`, both fine);
  this is the identifier-decoy effect showing up on the figure lane instead.

**Verdict: adopt BM25 for this KB at α ≈ 0.3** — the prose and decoy gains are
large and the diagram cost is one query's rank-5→6 slip with r@1 unchanged. A
per-lane α (lower for a query the visual arm should win) is the obvious refinement
and is left as a follow-on; it is not a reason to withhold the arm.

### `unified` fusion on the docling index

`VL_FUSION=unified` (both arms contribute candidates only; the cross-encoder
scores text and image in one probability space; no threshold), docling +
figure-scoped index:

| | text_gate τ0.72 | **unified** |
|---|---|---|
| prose r@1 | 0.938 | 0.938 |
| prose MRR | 0.958 | 0.969 |
| diagram r@1 | 0.762 | **0.571** |
| diagram r@5 | 1.000 | 1.000 |
| mixed r@1 | 1.000 | 1.000 |

**`unified` does not rescue the diagram lane — and the reason clears the whole
question up.** All 9 `unified` diagram misses (and all 5 `text_gate` ones) are
the figure page at **rank 2, behind a text chunk from page 2 of the correct
file**. Page 2 of every synthetic figure doc carries the line *"See the
`<name>` drawing."* — a caption the builder added. The docling chunker isolates
that sentence into a clean chunk; the cross-encoder scores it as a strong match
for the diagram query (right file, on-topic); the figure image lands at rank 2.

`_rank_of` scores a `diagram_only` query a hit only if a **visual** row of the
target page comes back first — a text row on the right file is a "miss". So this
metric is penalising *right document, wrong modality, rank 1–2*, on a corpus
whose synthetic docs contain a sentence purpose-built to name the drawing. **The
diagram-lane number is a synthetic-corpus artifact.** It is not a fusion failure
and no fusion mode fixes it, because there is nothing wrong: the figure page is
always retrieved (r@5 = 1.000). Resolving the diagram-lane ranking properly
needs a **real figure corpus** (P&ID / HMI PDFs with no "see the drawing"
caption text) — recorded as `honest-BLOCKED`.

`unified`'s lexical-decoy score is **7/8** (dense only — the BM25 arm lives in
`rrf_fuse`, not `search_unified`), the same `lex-05` ESP miss the dense
`text_gate` path had. BM25 (in the `rrf_fuse`/`text_gate` path) is what takes
decoys to **8/8**.

**Fusion verdict — keep `text_gate` + BM25, keep τ = 0.72:**

| config | prose r@1 | prose MRR | decoys | diagram r@1 |
|---|---|---|---|---|
| `text_gate` τ0.72, +BM25 (s3) | **1.000** | **1.000** | **8/8** | 0.762† |
| `unified`, no BM25 | 0.938 | 0.969 | 7/8 | 0.571† |

On the prose lane and the decoy lane — the two this KB's use case lives in —
`text_gate` at τ = 0.72 **with the BM25 arm** beats `unified` outright, because
`unified` cannot use BM25 as the fusion stage is written. The τ = 0.72
"non-transfer" only ever hit the diagram lane, and the diagram lane is a
synthetic-corpus artifact (below). So: **ship `text_gate` at τ = 0.72 + BM25 for
a docling KB**, and correct the `fusion.py` comment to say the τ is
prose-lane-valid on docling but was originally fitted to the fixed chunker.
`unified` would need a BM25 arm added to `search_unified` before it is
competitive here — recorded as a follow-on, not a blocker.

### P3.5 — S0 figure transcription — verdict: stays OFF for this KB

The diagram queries that lose rank 1 under docling lose it to a **text** chunk of
the right file's page-2 caption; the figure page is retrieved every time
(r@5 = 1.000). It is a ranking problem confined to a synthetic-corpus artifact,
not an answerability gap — S0 (transcribing the figure into the text arm) would
add a *second* on-topic same-file text row to that competition, not resolve it.
S0 remains a latency cost with no recall justification here. Re-decide it on a
real figure corpus alongside the diagram-lane question.

## τ re-decision

Swept on the docling + figure-scoped index (`RAG_CHUNK_STRATEGY=docling`,
`RAG_VISUAL_SCOPE=figures`, no BM25), 42 queries per point:

| τ | prose r@1 | prose MRR | diagram r@1 | diagram r@5 | mixed r@1 |
|---|---|---|---|---|---|
| 0.72 | 0.938 | 0.958 | 0.762 | 1.000 | 1.000 |
| 0.80 | 0.500 | 0.500 | 1.000 | 1.000 | 1.000 |
| 0.86 | 0.250 | 0.250 | 1.000 | 1.000 | 1.000 |
| 0.92 | 0.250 | 0.250 | 1.000 | 1.000 | 1.000 |

**There is no τ that serves both lanes on the docling index — the trend is
monotonic and steep.** prose r@1 goes 0.938 → 0.500 → 0.250 as τ climbs from
0.72; diagram r@1 is already maxed at 1.000 from τ = 0.80. At 0.72 the five
`diagram_only` misses are the figure page at **rank 2**, behind a docling chunk
of the synthetic page-2 caption ("See the … drawing"); raising τ flips all five
to rank 1 but every increment past 0.72 pulls more prose queries under the gate
too, because a docling chunk (one section, ~480 tokens) has a **lower**
query-cosine than the fixed chunker's ~1000-char slice did — it falls below a
threshold calibrated to the fixed chunker's distribution.

**`VL_TEXT_GATE` — verdict: keep τ = 0.72 for a docling KB, paired with BM25.**
Raising τ to close the diagram gap collapses prose (0.80 → prose 0.50), so the
gate's *range* does not survive the docling chunker — but its shipped value,
0.72, leaves the prose lane intact (0.938, and 1.000 once BM25 is added). The
diagram-lane loss at 0.72 is a synthetic-corpus artifact (see the `unified`
section), not a real regression. `unified` — the threshold-free alternative the
task's Part 2 pointed at — was tested and loses to `text_gate` + BM25 on both
prose and decoys because `search_unified` has no BM25 arm.
