# Host Memory Safety V1 — W5 live evidence

Captured 2026-10-07 on the live production Mac. W5 implementation is in the working tree at this capture.

## Runtime dependency and service recovery

The first `./launch.sh rebuild-mcp` attempt failed during the browser MCP's pinned Obscura clone because GitHub's TLS connection ended unexpectedly. No services were restarted on that attempt. The retry built successfully but exposed a memory MCP startup failure: `ModuleNotFoundError: No module named 'prometheus_client'` from `portal/platform/memory/memory_mcp.py`. `Dockerfile.mcp` did not install the dependency. Added `prometheus-client>=0.19.0` to the image's core dependencies and reran the supported `./launch.sh rebuild-mcp` command successfully. `./launch.sh restart-mcp` then refreshed service table snapshots after test cleanup.

The memory MCP was healthy after rebuild and restart. `GET /health` and `GET /metrics` each returned HTTP 200. The container environment reported:

```text
MEMORY_EXTRACT_MODEL=gemma4:e4b-it-qat-ctx8k
```

Before the probe, `/health` showed 69 memories, 221 entities, and 174 relations. A read-only `POST /admin/load-plan` for this single Ollama model returned HTTP 200:

```json
{"fits":true,"need_gib":7.1554694371297956,"available_gib":28.16634620167315,"headroom_gib":26.113959962502122,"idle_ollama_gib":0.0,"freeable_omlx_gib":4.052386239171028,"models":[{"engine":"ollama","model":"gemma4:e4b-it-qat-ctx8k","resident":false,"adds_gib":7.1554694371297956}]}
```

Immediately before the inference probe, `sysctl vm.swapusage` showed 907.69 MiB free and `memory_pressure -Q` reported 73% free. This was a single-model W5 acceptance request, not a multi-model live test; the W1 plan showed 28.17 GiB available. After the request and cleanup, swap free was 1,531.69 MiB. No concurrent inference test ran.

## Live store and cleanup

Sent a unique temporary `remember` request to `http://127.0.0.1:8920/tools/remember`:

```text
PortalMemorySafetyProbe20261007 is linked_to NercCipSafetyProbe20261007 for a temporary host memory safety acceptance check.
```

The MCP returned HTTP 200 with `stored=true`, `graph_updated=true`, and memory ID `230ef364-9724-47bb-8ea6-45766ad907e3`. A direct LanceDB read verified that ID in the memory table, both exact-name entities in `memory_entities`, and this relation in `memory_relations`:

```text
src=PortalMemorySafetyProbe20261007
dst=NercCipSafetyProbe20261007
rel_type=linked_to
source_memory_id=230ef364-9724-47bb-8ea6-45766ad907e3
```

The live entity rows were both type `Probe`; each had mention count 2 (entity extraction plus relation endpoint upsert). The post-store table counts were 70 memories, 223 entities, and 175 relations.

Cleanup called `/tools/forget` for that exact memory ID, then deleted only the two exact-name probe entities for `user_id='default'`. A fresh LanceDB connection verified 69 memories, 221 entities, and 174 relations, with zero matching probe memory, entity, or relation rows. Since the running MCP held an older cached Lance table view after the external cleanup, the supported `./launch.sh restart-mcp` command refreshed MCP processes; `/health` then independently reported the same 69/221/174 baseline and `graph.intact=true`.
