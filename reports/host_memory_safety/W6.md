# W6 — a memory gate that actually measures

**Disposition:** DONE. Live run 2026-10-07 15:08–15:10 UTC under [W6_watchdog.log](W6_watchdog.log) (no trip).

## Change

- `LoadGuard.host_free_bytes(base)` returns oMLX `final_ceiling − current_model_memory` plus idle (non-busy, non-pinned) Ollama residents, the guard's own admission formula. It returns None when oMLX status is unreadable.
- On each health cycle (every ~30 s, per worker), `BackendRegistry._update_memory_gate` pushes that value as `concurrency._last_free_gb`. `vm_stat` used% is read only when `shutil.which("vm_stat")` finds it, so it applies to a natively run pipeline only.
- `acquire_global` returns 503 with `Retry-After: 30` when `_last_free_gb < MEMORY_GATE_MIN_FREE_GB` (default 1.5). None fails open. `MEMORY_GATE_PCT` still applies where vm_stat exists.
- The active source is logged once per worker, and again when it changes. An unmeasurable host logs an ERROR saying the gate is open.
- Compose now passes `MEMORY_GATE_MIN_FREE_GB` to the pipeline. Before, neither gate variable reached the container.
- The unit-test conftest pins the new source as well as `memory_pct`, so no unit test reads the live host.

## Found on the way: worker INFO logs were dropped (pre-existing, fixed)

`logging.basicConfig` ran only in the uvicorn parent (`portal/platform/inference/__main__.py`). The spawned workers had no root handler, so every `portal.*` INFO line from a worker was dropped, including routing decisions, `Health check complete`, the W3 cancel lines and this gate's source line. Only WARNING and above reached Python's last-resort handler. `router/app.py` now configures the root logger when it has no handler. Verified: after the rebuild the workers log `Health check complete: 12/12 healthy` and `Memory gate source: host headroom (oMLX ceiling + idle Ollama)`.

## Live verification

Driving real headroom below the 1.5 GiB default would recreate the incident regime, which ground rule 6 and the watchdog exist to avoid. Instead the threshold was set, for one restart, between the headroom with and without a large oMLX model loaded. The gate then responds to a real memory change:

| UTC | State | oMLX headroom | Probe (body-less POST /v1/chat/completions, ×8) |
|---|---|---|---|
| 15:08:28 | `MEMORY_GATE_MIN_FREE_GB=27`, baseline | 38.6 GiB | 422 ×8 (gate open; body rejected after the gate) |
| 15:08:37 | loaded `gemma-4-26b-a4b-it-QAT-4bit` (15.5 GB) on oMLX | 23.4 GiB | — |
| 15:09:12 | after one health cycle | 23.2 GiB | **503 ×8** (pipeline log: 8 × 503) |
| 15:09:19 | unloaded the model | 38.5 GiB | — |
| 15:09:54 | after one health cycle | 38.5 GiB | 422 ×8 (cleared) |

The pipeline was then restarted at the default (`printenv` → 1.5) and `smoke_stream.sh` passed.

## Limits

The gate's value is up to one health interval (30 s) old. It is a coarse backstop; the cold-load guard is the per-load admission. With oMLX down, the gate fails open with an ERROR log, and the guard fails open the same way (`_headroom` returns None).
