## Addendum — real voice source + gen_seconds fix

s02 originally cloned a throwaway synthetic reference (a Kokoro clip reading a
filler sentence), not the operator's own voice. Redone against the operator's
actual registered reference: `~/.portal5/voice_profiles/chris/reference.wav`
(15.04s, 48kHz — the source used to register the seated `trainer:chris`
profile), copied to `~/AI_Output/uploads/chris_voice_reference.wav` per Rule
11 (not committed to git — it's a voice biometric, kept in the shared
workspace like any other user file, not repo-tracked).

While wiring this up, found and fixed a real bug in `auk_mcp.py`'s
`synthesize()`: when a `reference_audio_url` was given, `gen_seconds` was set
from the *reference clip's* duration instead of the *text's* estimated
duration (`_duration_s(ref) or _tts_seconds(text)`). Against the old 6s
synthetic reference this was barely visible; against the real 15s reference
it made the model pad/hallucinate extra speech to fill 15 seconds for a
4-word phrase (confirmed non-silent, sustained RMS across the full clip —
not just padding, actual invented content). Fixed to always use
`_tts_seconds(text)` for this path (`portal/modules/media/tools/auk_mcp.py`).
Service restarted (`launchctl kickstart -k gui/$(id -u)/com.portal5.auk`);
the corrected item now produces 2.4s for the same phrase, matching the
non-cloned baseline (s01).

This bug is orthogonal to the seat-relevant items (paralinguistic/edit/
separation/enhancement never pass `gen_seconds` from a reference this way)
and does not change the 8/8 mechanical seat rate above. It's a real fix to
the `synthesize` tool's cloning path, independent of promotion.
