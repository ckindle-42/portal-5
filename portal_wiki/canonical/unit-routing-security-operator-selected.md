# Security Is Operator-Selected, Never Auto-Routed

`auto-security` and `security-reviewer` declare `router: false` in
`config/portal.yaml`. The `auto` router has no path to either: they are absent
from `_VALID_WORKSPACE_IDS`, so absent from the grammar enum and the
post-classification check, and `_build_router_prompt` filters both the label
block and the few-shot examples to ids the router may actually return. Both
stay in the Open WebUI dropdown and callable by id — `auto-security`,
`auto-security::<variant>` — behaving exactly as before when selected
directly.

## Deleted, not wrapped

The global router holds no security entries at all: `_WORKSPACE_ROUTING` and
`_SCORER_VARIANT_MAP` lost theirs, the redteam-vs-security tiebreak is gone,
`_VARIANT_INFERENCE_TABLE` covers `auto-coding` only, and
`routing_descriptions.json` / `routing_examples.json` no longer name or teach
the lane. Routing *within* security — role, variant, model, tools — is
unaffected; that is the lane's own business.

## Why

Exclusion alone is worse than the status quo. Measured on the 14 security rows
of `tests/wfe/suites/routing_production.jsonl`, with the label simply removed
the classifier scattered them into `auto-general-uncensored` (6),
`auto-bigfix` (3), `auto-spl` (2), `auto-documents` (2) and `auto-coding` (1)
— answered by normal lanes, with those lanes' models and tools, and never
declined.

So `detect_router_handoff` runs ahead of Layer 1, mirroring
`detect_harmful_intent`, and sends the request to the workspace's
`router_fallback` lane (`auto-daily`), appending the workspace's
`router_handoff_note` so the lane declines and names the workspace to select.

## The detector is the lane's own vocabulary

`_ROUTER_HANDOFF_KEYWORDS` is the union of the security lane's discipline
keywords and every role/variant signal set (redteam, blueteam, pentest,
purpleteam…), at `_ROUTER_HANDOFF_THRESHOLD = 2`. Nothing is invented and the
role sets stay inside security. The union matters because the retired
`_WORKSPACE_ROUTING` entry was only ever a fallback behind Layer 1's label, so
on its own it recognised offensive phrasing and missed most blue-team work
(Sigma/YARA/IDS/CVE/IR): 7/15 alone, 29/29 as the union, with 0 false
positives across 77 non-security prompts.

The red half of that vocabulary stays even when the offensive-generation
variants are gated off by [[unit-module-security-redteam]]. The detector
matches strings in order to refuse; a bouncer is not a generator, and
stripping red terms would send red asks back to scattering.

## Evidence

`routing_production.jsonl`'s 14 security rows expect `auto-daily` plus an
answer naming the workspace, each carrying a `note` for provenance; they are
generated by `tests/wfe/suites/build_routing_production.py` off the same config
flag, and declining is correct for them, so they carry no
`refusal_is_failure`. `scripts/routing_regression.py` applies the gate before
the layers, so `tests/routing/baseline.json` records where requests actually
go rather than where keyword scoring would have sent them.
