# ICS/OT Module

## Tools

`icsot_mcp` (:8936) — passive, read-only industrial-protocol intelligence.
`list_ics_protocols` enumerates the recognized ICS ports and their dissection
tier (`full` for Modbus/TCP via `scapy.contrib.modbus`; `identify` — port and
header only, with a documented extension hook — for DNP3, S7comm, EtherNet/IP,
BACnet, Niagara Fox, OMRON FINS). `dissect_pcap` reads a capture and returns
per-protocol counts, a Modbus function-code breakdown, top conversations, and
behavior -> ATT&CK-for-ICS technique tags. `asset_inventory` derives an ICS
asset list (host, protocols seen, HMI/EWS-vs-device role hints) from captured
conversations. `correlate_advisories` cross-references an observed vendor to
recent CISA ICS advisories through the `vulnintel` module (in-process import,
no network round-trip to self).

The module also completes `mitre_mcp`'s ATT&CK-for-ICS coverage: the ICS
technique set from MITRE's official ics-attack STIX bundle
(`portal/modules/security/core/siem/mitre_ics_techniques.json`, regenerated by
`scripts/refresh_mitre_ics_catalog.py`) is merged into the technique index
with `matrix: "ics"`, so `mitre_technique_lookup` / `mitre_techniques_list` /
`mitre_data_sources_for_technique` resolve `T0xxx` and the newer `T1xxx` ICS
identifiers, not just Enterprise.

## Workspaces

- `auto-security` — OT/ICS traffic analysis
- `auto-spl` — ICS detection-engineering context

## Why

The platform's stated core is OT/ICS security and the OT half had zero
tooling — `modbus` / `dnp3` / `s7comm` / `ethernet-ip` returned no files. This
module is deliberately passive: it parses provided captures and named-protocol
payloads and never transmits an ICS frame, polls a live PLC, or writes a
coil/register — writing to a live process device can trip a plant. Any active
capability is a separate operator `[GATE]`. Capability tiers are stated
honestly in tool output: a protocol the server only identifies by port says
so. The module gates the `icsot` fleet id and its workspaces, both derived
from their `module: icsot` tag in `config/portal.yaml`.
