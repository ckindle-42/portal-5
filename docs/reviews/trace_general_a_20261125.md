Derived from current `config/portal.yaml`, `config/personas/`, `config/backends.yaml`, the memory MCP manifest, the Open WebUI initializer, router code, tests, and WFE plans. The inventory is **8 general workspace roots + 17 declared variants = 25 workspace entries; 15 `module: general` personas with filenames sorting A–L; 9 memory MCP tools; and 2 automatic-memory features**. The static trace is Open WebUI model/preset → `scripts/openwebui_init.py` seeds workspace and persona presets → Pipeline `/v1/chat/completions` resolves persona, auto route, variant, model override and image fallback → safety guard and request-context preparation → healthy backend candidates and seat hint → tool loop or model output → `/v1/trace` metadata/spans and metrics. `config-only` validation does not establish that engines, templates, model files, MCP connections, or seeded presets are healthy on the live stack. I did not run live services or claim live success.

## Memory MCP on 8920

`config/portal.yaml` declares `memory` on 8920, exposed to Pipeline and IDE. Compose binds host `127.0.0.1:${MEMORY_MCP_HOST_PORT:-8920}` to container 8920 and mounts the separate `portal5-lance` volume at `/app/data/portal5_lance`. The memory server exposes no shared filesystem tool, so shared workspace path rules do not apply. User ownership is default operator scope or evaluation-run scope. Extraction uses the Pipeline Ollama proxy with a 30-second timeout and is best-effort; embeddings and LanceDB operations have separate error paths. The manifest and native wrappers share `graph_memory.py` implementations.
