## What did not recover: `floor_known_recall` is still 0.0

Two concrete, evidenced blockers remain, neither of them the classifier:

1. **`wineventlog:security`/`xmlwineventlog:sysmon`/`xmlwineventlog`
   (lowercase, colon-qualified) classify at 0% coverage in THIS capture --
   85, 35 and 121 records respectively, all unmapped -- while the
   differently-cased `WinEventLog` sourcetype (same underlying Windows
   Security data, an older Splunk TA naming) classifies at 79.6% coverage
   through the identical code path. The classifier's EventCode extraction
   (`_dig` over `EventCode`/`EventID`/...) is finding nothing on the
   colon-qualified records captured this run -- most likely because Splunk's
   modern `wineventlog:security` sourcetype ships less-flattened raw XML
   that this pipeline's `_parse_raw_kv` (built for `key=value`/JSON `_raw`)
   does not extract EventCode from, where `WinEventLog`'s legacy TA already
   flattens it. `bots_answer_key.py`'s answer-key techniques are declared
   against exactly `wineventlog:security`/`xmlwineventlog:sysmon` -- so even
   a discovered cluster built from real AS-REP-roasting activity in this
   corpus would carry an empty/unclassified shape for those steps in this
   capture window, never matching the anchor spine.
2. **`discovery.enrich()`'s shape-distance metric cannot recognise a short
   spine inside a long window.** `_shape_distance` normalizes the longest
   common subsequence by `max(len(a), len(b))`. An L4_WINDOW unit's
   `shared_shape` can run to thousands of steps (`cc-0004` below carries
   20,000+); a 2-3 step answer-key spine embedded inside it as a genuine
   subsequence still scores a distance near 1.0 (`1 - lcs/max(m,n)`), far
   above `similar_max=0.45` -- so `enrich()` reports `resembles_nothing` for
   every cluster in this run regardless of whether the real technique is
   present in it. This is a pre-existing discovery-algorithm limitation, not
   introduced by T.1/T.2, and not one this task's scope (the classifier and
   the three guard holes) covers.

Per T5 (floor gates the product): `product_cousin_recall: 0.2` and every
per-transformation number below describe a run whose floor is unmeasured,
not zero-and-trustworthy. **T.4 does not proceed from this diagnostic** --

shapes") is not met. The classifier defect that motivated this task is
