**2. The six design decisions**

1. **Assessment entry:** one shared `assessment.assess_part` service performs listwise council judgment of the actual governing Part over full candidate text. Gaps, analysis, scenarios and proposal rejudgment become adapters to that service; V3 field comparison stops producing substantive verdicts.
2. **Deterministic gate:** retain existing applicability calculations, source integrity checks, reference traversal and `constraints.compare_constraint`. Remove semantic selection and first-duration choice from the gate; only explicitly aligned source operands reach arithmetic.
3. **Same obligation:** use a narrow source-grounded model alignment pass before the gate, with categorical SAME/DIFFERENT/UNKNOWN outcomes and clause-level bindings. No word, folder, quantity-equality or confidence threshold decides whether two duties are comparable.
4. **Verdicts:** retain FULL/PARTIAL/NONE for documentary coverage, with explicit evidence and known gaps; retain uncertainty separately. Public actual-scope resolution must also satisfy applicability and provenance contracts; conditional documentary support must not be presented as an unconditional compliance determination.
5. **Solutions:** represent a proposed edit as exact source-slice replacements or additions, and rejudge the resulting virtual document state through the same service. All draft-producing paths, including standard-transition drafts, use this rule; none may assert success from governing-text containment.
6. **Acceptance:** retain the 26 named seed cases in section 7 and add the concrete cross-path contract checks there. Acceptance requires actual routed model results and run-specific evidence, not a historical latest-run query or only mocked component tests.

**3. Chosen target architecture and what is removed from revision 1**

Use the existing `assessment.py` as the orchestrator, `gate.py` as deterministic preparation, `council.py` as the unchanged satisfaction engine, and `Repository` as the persistence authority. Avoid an additional framework, independent result database, or new model roster.

Remove the previous design's new formal obligation planner, two plan-validator calls, compulsory council-per-criterion diagnosis, and a second expression rollup that could overrule the Part council. The source does not provide a reliable formal plan, and the actual question can be judged from the full Part, its lead-in, definitions and references. Generated atom structure must not silently narrow that question. Keep the existing expression evaluator for already explicitly supplied/validated formal expressions; do not synthesize such expressions from OR/AND word tests and treat them as ground truth.

A narrow alignment reader selects clauses and operands; it does not decide FULL/PARTIAL/NONE. One ordinary listwise council then judges the full obligation, including all mandatory conditions, allowed alternatives and exceptions. The existing council response is the satisfaction decision. One explicit, bounded source-linked explanation call then identifies the covered commitments and shortfalls needed to project FULL/PARTIAL/NONE. It cannot overturn the council. Actual probes showed that asking the unchanged council to emit additional report fields was inconsistent, so that earlier mechanism is removed. This explanation stage is new semantic reporting and needs qualification; it is not merely JSON formatting or a second council.

Dependency direction:

```text
MCP gaps / analyze / scenario / draft-revisions
    → snapshot/candidate acquisition adapter
    → assessment.assess_part
        → source resolution and applicability
        → obligation_alignment.align_part (semantic clauses/operands)
        → gate.run_gate (aligned input only; existing arithmetic)
        → council.run_council (unchanged internals)
        → assessment_report.explain (one bounded source-linked report)
        → validate consistency and evidence / project one AssessmentResult
        → Repository.record_assessment
    → CoverageCell / Determination / scenario response projections

operations.propose / change_pipeline.draft_revisions
    → scenario edit overlay on the pinned snapshot
    → the same assessment.assess_part
    → validated proposal or explicit failure, never self-certified closure
```

`assessment.py` calls `run_council` directly. `operations.judge` delegates inward to assessment; assessment does not call operations. Proposal orchestration belongs outside the assessment service, preventing recursive draft generation during rejudgment.

**4. Exact shared contracts**

Implement the new records in `determination.py` alongside the existing projection types. Interface notation below is not application code.

`AssessmentRequest` contains `requirement_id`, full governing source bundle, `scope`, `scope_basis`, `effective_on`, `known_at`, `org_id`, `kb_id`, a pinned `CorpusSnapshot`, the candidate acquisition receipt, and optional `ScenarioOverlay`. Production must explicitly supply these through a context factory; silently using an unrelated default org graph is forbidden. Runtime dependencies—source resolver, configured seats/quorum, `SeatFn`, repository—are injected through `AssessmentContext`, not included as serializable request data.

`CorpusSnapshot` contains manifest and index-generation fingerprints, Lance table/version where applicable, document revision hashes, candidate identities, acquisition mode RETRIEVAL/EXPLICIT_SET, and completeness status. The full governing graph is pinned separately; filtering rows for a request must not discard referenced governing text. Dates or exact scope facts that cannot be resolved remain unknown, not invented.

`SourceSlice` contains an exact `ref`, document ID, revision/content hash, stored chunk ID, section/heading/page locator, exact text, and half-open character offsets **within that stored chunk text**. Keep the original document/Docling coordinates separately; they are not interchangeable with chunk-local offsets. Full chunks and referenced context accompany slices. Verify quote equality against the pinned source, not merely against text supplied by a model. A proposed slice has its own scenario revision and role, never an effective-corpus anchor.

`CandidateSet` contains full source records, original retrieval annotations, acquisition receipt, and unresolved source records. Retrieval scores and `relevant` flags remain diagnostics. Every supplied locatable text candidate receives semantic reading in the alignment stage; failures and UNKNOWN links cannot be discarded to manufacture an absence. Nontext pointers cannot become quoted documentary evidence. Returning full text and identifiers already present in a retrieval result is an additive transport change, not a retrieval algorithm change.

`align_part(governing_bundle, candidates, scope_context, runtime) → AlignmentResult` is implemented in new `obligation_alignment.py`:

- Use the existing configured seats independently for the narrow reading pass, through existing `SeatFn`, and the existing roster/quorum rule for categorical agreement; no new roster, confidence threshold or confidence-weighted vote. Revision 1’s single-seat assumption failed the 40-day same-duty control in an actual diagnostic. The council reads the selected operative sources with their necessary original context. Exclusion decisions require independent source-valid quorum and remain fully auditable; an uncertain exclusion is not dropped. This avoids reinserting irrelevant or non-operative records as apparent substantive deficiencies after alignment. The alignment reader never receives a prior determination, gold label or approved coverage verdict.
- One request per Part is the normal unit. A governing-to-internal request contains full Part and lead-in, cited definitions/reference text, scope context, and the complete candidate set. An internal-pair identity request presents LEFT and RIGHT as its two operands, with the target requirement ID as metadata; it must not substitute the target governing text for LEFT. Separate the task of duty identity from the later task of satisfaction. Different constraint values are not different triggers. For each candidate, return one or more exact operative clause slices and relation SAME/DIFFERENT/UNKNOWN to the governing duty. A mixed-topic chunk must return separate clause records. Return unresolved context explicitly.
- SAME: the clause prescribes or implements the governing activity/object, for an overlapping target population and compatible trigger. Different deadlines, weaker wording, omitted conditions, or incomplete satisfaction do not make it DIFFERENT. A clause may implement only part of the duty and still be SAME.
- DIFFERENT: source wording positively establishes another activity, another triggering duty, disjoint population, or non-operative contents/reference material. Shared standards and document folders do not determine this. A cross-cutting CIP-003 policy can implement a CIP-007 obligation.
- UNKNOWN: the source or context does not establish either relationship. Return the precise missing fact; no arithmetic may use this record.
- Each record contains `link_id`, governing refs/slice IDs, candidate refs/slice IDs, activity/object/trigger/population readings, `population_overlap` OVERLAPPING/DISJOINT/UNKNOWN, rationale, missing facts, `source_function` (OPERATIVE_COMMITMENT, DEFINITION, AUTHORITY_RECORD, CROSS_REFERENCE_TABLE, CONTENTS, OTHER) and `constraint_bindings[]`. Source function is read semantically, not inferred from a date, filename or keyword. Source-validation failure turns it into UNKNOWN, not a negative relevance decision.
- For internal-to-internal conflicts, request direct pair decisions only for clauses already tied to the same governing duty. Two clauses' broad relevance to a Part is not a transitive proof that their constraints concern the same sub-duty. Record direct SAME/DIFFERENT/UNKNOWN with the same contract. This second batch is needed only when testing potentially competing operative prescriptions. Do not enumerate comparisons merely because chunks contain numbers.
- Preserve complete input coverage: every candidate ID must occur in the alignment output. Omission, invalid JSON, duplicate inconsistent IDs or a truncated response produce an alignment failure. Do not retry until a favorable answer appears. No implementation fallback to keywords.

`ConstraintBinding` contains both exact operand slices (digit value, unit, qualifier), the matched duty/trigger, existing constraint kind, both parsed `Quantity` values, and the SAME link ID. The model selects the operands; deterministic validation checks their literal values. In “thirty-five (35) calendar days”, bind digit `35` and the existing calendar/day operands rather than introducing a spelling heuristic. All relevant quantities in a multi-constraint duty have their own bindings. Missing direction or ambiguous binding remains unresolved.

`gate.compare_aligned(binding, link) → ConstraintResult` rejects anything except source-verified SAME/OVERLAPPING bindings. Call existing `compare_constraint` unchanged. Preserve EQUIVALENT/MORE_RESTRICTIVE/LESS_RESTRICTIVE/INCOMPARABLE and its explanation. `assessment._compare` becomes only a compatibility delegate to this function; no nonnumeric entailment remains there. Literal equality of two complete clauses does not establish relevance by itself.

`GateResult` retains the existing council packet keys and adds the full governing text/lead-in as authoritative `governing_unit.verbatim_text` and `constraint.text`, source refs, aligned per-duty constraints, original candidate context, exclusions/unknowns and acquisition completeness. The substantive candidate list contains SAME operative commitments and unresolved potentially operative inputs. Relevant definitions or authority context are supplied separately only where needed to resolve a stated dependency; they do not become extra obligations. Do not reinsert DIFFERENT chunks, contents, duplicated standards tables or unnecessary administrative records as substantive candidates after the reader excluded them. Preserve every original chunk, relation, source-function decision and rationale in the acquisition/assessment trace. Excluded source refs are not support refs in the council allowlist. A source-invalid or non-quorate exclusion becomes UNKNOWN; the complete boundary cannot be certified while that uncertainty matters. This is semantic selection after retrieval, not a new retrieval heuristic.

The existing scalar `quantity_outcome` is populated only when it corresponds to one unambiguous aligned constraint. For multiple constraints, retain the per-binding list and leave the scalar empty. No first-number summary. Do not allow `subject.char_end` to trim the governing rule: R2.4 must contain its implementation duty and complete exception, not just “or delegate.” Derive the responsible actor from the verified governing lead-in, and distinguish it from the actor authorized to approve an exception. Preserve decimal part references as source text rather than splitting at their periods. These are packet assembly changes; the reviewed arithmetic is untouched. Provide all actual reference texts for exception evaluation, and flag unresolved closure edges; do not substitute “text not supplied” as if the reference had been checked.

`CoverageExplanation` is produced by new `assessment_report.explain(prepared_packet, validated_council_result, source_catalog, runtime)`. It makes one explicit call through the first configured seat’s existing transport with a separate reporting system prompt; it is not a call through `_SEAT_SYSTEM` and is not a voting council seat. Council seats remain sealed and never receive this report or another seat’s answer.

The reporting input includes the unchanged satisfaction decision, agreeing opinions and their source-valid citations, arithmetic results, and the same authoritative governing/operative texts. It contains no gold labels or future proposal. The model must preserve the council decision and return `documentary_coverage`, `covered[]`, `gaps[]`, `uncertainties[]`:

- `covered[]`: independently satisfied substantive commitment, governing source-slice IDs and internal source-slice IDs. Reporting a failed cadence must not erase a separately source-backed commitment to perform the evaluation.
- `gaps[]`: concrete missing/deficient duty, kind OMISSION/WEAKER_COMMITMENT/CONTRADICTION/OUTDATED_LANGUAGE, governing slice IDs, internal counterevidence slice IDs or completed boundary proof ID, and a specific missing commitment.
- `uncertainties[]`: missing facts or incompatible interpretations, with source IDs and reasons.

The application supplies immutable selectable IDs for existing source paragraphs/lines and numeric occurrences, preserving full context. These are locators, not new retrieval chunks or semantic segmentation. Models select IDs; the application emits the exact stored text. Multiple selected slices remain separate quotes. No model-reconstructed verbatim quote, ellipsis splice, approximate source name or generated character offset is accepted.

Use strict source validation at both boundaries. Wrap the ordinary council `SeatFn` to record raw responses and reject an off-packet/unresolvable citation as a failed seat before it can contribute a vote; retain the rejection cause. This supplies stricter validation without changing council internals. For a valid council conclusion, retain the decision-agreeing opinions as support provenance and dissent separately. The explanation’s internal support/counterevidence IDs must resolve within the operative sources cited by those agreeing opinions; it cannot rehabilitate an excluded source or use a dissent-only citation as consensus evidence.

Consistency rules are closed: report FULL only with council SUPPORTED; report PARTIAL only with council PARTIAL or CONTRADICTED and nonempty covered plus grounded gaps; report NONE only with council ABSENT or CONTRADICTED, no supported substantive commitment, and a valid absence/explicit-contrary basis. Report UNRESOLVED when the packet, evidence or decision cannot support a valid explanation. A disagreement, invalid ID, missing report, required absent boundary or incompatible report shape becomes U11/U04 as appropriate; do not silently use the more favorable output or reconstruct a gap from keywords in a rationale. Semantic completeness cannot be proved by source-ID validation alone: the positive and weaker-cadence reporting controls are mandatory qualification tests.

The reporter makes a new semantic characterization of partial extent because the existing coarse council result does not provide it. It is subordinate to, and cannot reverse, satisfaction judgment. This dependency is explicit in the architecture and measured separately. It adds one report call per Part, not a new formal planner or council per criterion. No automatic retry/repair loop is authorized; failed reports remain unresolved with their raw evidence.

`AssessmentResult` is the **single authority**: `assessment_id`, `run_id`, `engine_version`, input fingerprint, requirement ID, applicability/basis, `documentary_coverage`, `coverage`, `substantively_resolved`, original council result, covered commitments, grounded gaps, uncertainties, confirmed conflicts, comparison uncertainties, selected source slices and acquisition/boundary receipt. `CoverageCell`, `operations.Determination`, `AtomResult` and `RequirementResult` are projections, not alternative decision engines. Every projection exposes its assessment ID.

**5. Verdict, scope, absence and repair semantics**

The assessment is **documentary coverage**, not an attestation that patch reviews or mitigation activities actually occurred. Preserve operational-evidence expectations and any requested evidence period separately. Measure examples do not become additional mandatory duties merely because they mention records.

- **FULL:** all applicable mandatory duties in the whole Part are satisfied by operative source-backed commitments, or a valid applicable exception; no unresolved decision-changing omission, quantity or current-source contradiction. A stricter numerical bound satisfies the floor. One adequate policy or procedure can suffice; require neither both document classes nor a percentage of matching fields.
- **PARTIAL:** at least one substantive commitment is supported and at least one specific mandatory shortfall is demonstrated. State the covered commitment, missing/weaker duty and evidence. A wrong evaluation cadence can coexist with a supported commitment to perform the evaluation. A matching actor or number alone is not partial substantive coverage.
- **NONE:** no substantive duty is satisfied within the assessed boundary. Distinguish absence from explicit contrary evidence. Empty top-k results or unrelated spans alone do not prove absence.
- **UNRESOLVED:** source, scope, semantic alignment, quantitative binding, council quorum, response contract or assessment completeness prevents the claimed result. Preserve known covered commitments, the missing fact and the original council output. It is never converted to PARTIAL.
- **NEEDS_REVIEW:** competing source-backed interpretations, conflicting current commitments, or inconsistent approved decisions require a choice. Failure to run a model is operational uncertainty, not a fabricated SME dispute. Preserve existing retrieval-error compatibility where needed, with `substantively_resolved=false` and an explicit failure stage.
- **NOT_APPLICABLE:** existing applicability logic determines the duty does not apply. No substantive council or gap generation is needed.

Map council SUPPORTED to documentary FULL, PARTIAL to documentary PARTIAL, ABSENT to documentary NONE only after the evidence/absence contracts pass. CONTRADICTED maps to PARTIAL if a substantive commitment remains covered, otherwise NONE. An arithmetic INCOMPARABLE is uncertainty, not contradiction. Different-obligation records trigger no comparison at all. A true same-duty 40-day maximum versus required 35 days is weaker; 30 versus 35 is stricter support. Two compatible stricter prescriptions are not a conflict merely because their numbers differ. Preserve intentional-strictness review as an advisory without inventing intent or downgrading support.

**Scope reconciliation:** use `applicability_state` as the shared applicability outcome without changing its internal rules. The actual baseline's corpus-derived scope is UNKNOWN. Production must not relabel it as an authenticated declaration. If a caller explicitly asks for documentary evaluation under an assumed scope, run a named conditional assessment with that assumption; preserve `documentary_coverage=FULL` when supported, but the actual-scope projection remains `coverage=UNRESOLVED`, `substantively_resolved=false`, with the missing scope declaration. Only a resolved applicable scope permits the ordinary FULL/PARTIAL/NONE public projection. All controlled acceptance fixtures declare their test scope; the real-corpus case asserts conditional documentary support until a confirmed scope exists. This is an explicit correction to the old mixed-scope behavior, not a new applicability heuristic.

**Absence boundary:** successful search execution is insufficient. The current `BoundarySearch.exhaustive` checks query/generation metadata and flags; it does not prove that the supplied population was exhaustively read. Add a required completeness receipt with eligible document/section identities, revision hashes, actual examined set, candidate rejection links, omissions and acquisition mode. `BoundarySearch.exhaustive` and `Repository.record_boundary_proof` must reject an absence claim if this receipt is missing or unaccounted sections exist. Existing old proofs remain historical and cannot satisfy the new engine contract. A complete explicit fixture set can prove its own boundary. Production top-k retrieval without an independently completed search boundary yields uncertainty for omissions. Do not build a new corpus-scanning or retrieval engine under this assignment, and do not claim whole-corpus gap detection is solved if that receipt is unavailable.

A positive operative witness can prove documentary support within a declared retrieval boundary without proving whole-corpus absence of contradictory policies. Report the boundary, retain all supplied contrary inputs, and do not claim unexamined documents were checked. Distinguish this from a gap inferred from silence.

**ScenarioOverlay** contains base snapshot fingerprint plus ordered, nonoverlapping edits: REPLACE requires exact source revision/chunk/range and expected-old-text hash; ADD requires a named target document/section or an explicitly new proposed procedure. Reject stale hashes, overlapping edits and ambiguous replacements. Construct the edited source state once, then run the same service. Preserve unaffected paragraphs, policies and other relevant documents. Never append contradictory old wording during a replacement or drop all old candidates indiscriminately. A bare legacy patch string without a target defaults to ADD, labeled as such; it cannot claim it replaced an existing rule.

`operations.propose` returns a proposal only as a proposal. A closing draft requires after-assessment FULL, all claimed gap identities closed and no previously supported affected duty weakened. Reassess the target and every affected Part identified by existing source links plus the affected Parts in the current run; do not claim safety for unexamined dependencies. Unknown dependency coverage limits the closure claim explicitly. One generation attempt and one rejudgment per gap package; failure preserves the gap with FAILED_VALIDATION. Missing factual values produce BLOCKED_MISSING_FACT; no invented operators, historical completion dates or installed controls. Draft validation never changes the actual assessment or approved mappings.

**6. File/function changes, persistence and migration order**

`core/assessment.py`: add `assess_part(request, context) → AssessmentResult`. It resolves sources, calls alignment, calls the deterministic gate, calls the existing council through the strict source-validating transport, calls `assessment_report.explain`, validates consistency and evidence and persists the assessment.
