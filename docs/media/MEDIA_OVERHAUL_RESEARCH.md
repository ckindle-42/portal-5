## Executive Summary

Portal 5's three disabled media modules (`modules.image.enabled: false`, `modules.video.enabled: false`, `modules.music.enabled: false` in `config/portal.yaml`) suffer from both **model/engine staleness** and **structural platform incompatibilities** that prevent them from running reliably even when enabled:

1. **Cross-cutting platform blockers (affecting all three modules):**
   - **60s MCP dispatch kill (`TOOL_DISPATCH_TIMEOUT_S`):** `portal/platform/inference/tool_registry.py:56,599` aborts any MCP `tools/call` at **60 seconds** unless the server's `tools/list` advertises `_meta["portal5/timeout_s"]` (via `align_native_tools` in `portal/platform/mcp_host/tool_support.py`). None of `mflux_mcp.py`, `video_mlx_mcp.py`, or `music_minimax_mcp.py` sets this timeout, so synchronous image/video jobs exceeding 60s are killed mid-flight and penalized by the circuit breaker.
   - **20-hop tool loop cap (`MAX_TOOL_HOPS`):** `portal/platform/inference/router/workspaces.py:128` caps tool loops at 20 hops. LLMs cannot sleep between `*_status(job_id)` polls, so tight polling burns all 20 hops in ~20s before a multi-minute job completes unless `*_status` performs **server-side long-polling** (wait 15–20s per call before returning).
   - **Zero `LoadGuard` coordination:** `portal/platform/inference/load_guard.py` coordinates Ollama and oMLX (and already exposes `POST /admin/reclaim-idle` with `{"need_gib": <float>}` at `portal/platform/inference/router/app.py:51` / `handlers.py:318-346`), while media MCPs only read a point-in-time `vm_stat` snapshot (`portal/modules/media/tools/_admission.py`) and never call `/admin/reclaim-idle`. Meanwhile `music_minimax_mcp.py` holds ~22 GB permanently in-process until process exit (`docs/TASK_MEMORY_FOOTPRINT_REDUCTION_V1.md` §4.1).
   - **Workspace model garbling / routing drift:** `auto-audio::image` and `auto-audio::video` bind `granite4.1:8b-ctx16k` (affected by `OMLX-GRANITE-8B-MXFP8-GARBLE-001` if ever re-aliased to oMLX), `auto-daily` still lists `minimax_generate`/`minimax_status` even with `music` disabled, and `config/portal.yaml` aliases (`auto-image`, `auto-video`, `auto-music`) have `remove_after: 2026-12-31`.

### 1.3 Image Recommendation & Memory Coexistence
- **Primary Pick:** **Upgrade `mflux` to `>=0.24.0` (Python 3.11+ venv)** and standardize on a 3-model roster:
  1. **`flux3-klein` (Q8/Q6, `mflux-generate-flux3` / `mflux-generate-flux3-edit`, 16 steps)** as the **quality + multi-ref editing default** (if FLUX Kommunity License <$5M/yr is acceptable) — OR **`flux2-klein-4b` (4 steps, `Apache 2.0`)** as the **default fast T2I** (`generate_image` default = `flux2-klein` at **4 steps** for instant <20s responses, with `flux3-klein` for high-detail/multi-ref, and `qwen-2.1-turbo` at **8 steps** for typography/instruction editing via `mflux-generate-qwen-2.1-edit`).
  2. Retire `FLUX.1-schnell`, `FLUX.1-dev`, and legacy 20B `qwen-image` from defaults (keep optional env alias only).
- **Fallback Pick:** **`Z-Image-Turbo` (`Apache 2.0`, 6B, 8 steps)** via `mflux-generate-z-image-turbo` when a fully permissive `Apache 2.0` photorealistic checkpoint is required without FLUX Kommunity or Qwen Research terms.
- **Memory Budget & Coexistence with oMLX / Ollama:**
  - Peak working set: `flux2-klein-4b` Q8 (~14–18 GB) / `flux3-klein` Q8 (~12–16 GB est.) / `qwen-2.1-turbo` Q8 `--low-ram` (~8–13 GB).
  - **Subprocess-per-job** remains mandatory (`TASK_MEMORY_FOOTPRINT_REDUCTION_V1.md` §4.1): MLX wired Metal buffers do not reliably return to macOS until process exit; keeping `mflux_mcp.py` as a ~64 MB launchd supervisor that spawns `mflux-generate-*` per job guarantees **0 GB resident between jobs**.
  - **Warm time:** Cold load from local HF cache on NVMe is ~3–8s (**Estimated**). Adding `--compute-precision float16` and fixing `klein` from 28 → 4 steps cuts generation time by ~4–7×.
  - **LoadGuard integration:** Before `admit("mflux:...")` refuses on low memory, `mflux_mcp.py` (or `_admission.py` when `PIPELINE_URL` / `PORTAL_API_KEY` is configured, keeping Rule 3's zero-import boundary via HTTP) should call Pipeline's existing `POST /admin/reclaim-idle` (`{"need_gib": <shortfall>}`) so a resident 25–30 GB idle LLM is evicted instead of blocking a 14 GB image job.
